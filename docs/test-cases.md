## 1. 验收方法与素材

- 单元测试：总分/null、证据规则、状态转换、缓存键、生命周期等确定性逻辑。
- 接口测试：上传、授权、任务、报告和删除。
- 少量端到端测试：单图闭环、拒评/降级、批量选片、最终导出与清理。
- 真实能力评测：人脸定位、来源凭据、评分重复性和建议质量。模拟适配器仅测错误路径，不替代真实引擎验收。
- 人工验收：解释是否有图片依据、是否尊重对象、摄影建议是否可执行、排名是否如实呈现限制。

素材须有用途授权和来源记录；真实拍摄、原生生成、AI编辑、有可信凭据、签名损坏、未知签发者、截图、移除元数据、压缩、伪造EXIF、人脸遮挡/侧脸/多人/模糊等。预先记录期望证据状态，不依赖文件名“real/AI”判真值。

可用合法夹具构造坏文件、伪元数据和签名篡改副本；用户后续已授权用8张指定优化版进行测试。八人宫格用于锁定版本，不作为分数或来源真值。

## 2. M0必须补齐的量化标准

| 项目 | 制定方式 | 通过门槛状态 |
|---|---|---|
| 上传大小/像素/批量上限 | 按目标机器资源验证，明确边界值 | 待M0提出并审阅 |
| 面部可评门槛 | 按像素、角度、模糊、遮挡样本逐维度制定 | 待M0提出并审阅 |
| 同图重复波动 | 固定输入/配置重复评估，报告各项范围与总分波动 | 待M0锁定次数与允许波动 |
| 背景干扰 | 保持同一裁脸输入，改变整图背景；核对面部请求是否一致 | 输入隔离必须成立；输出波动按稳定性门槛 |
| 延迟与成本 | 测本地处理、每模块、失败/重试费用和额度口径 | 真实记录后确定可接受值 |
| 排名/平局规则 | 使用已审阅算法，检查平局、循环和缺边 | V0.3前锁定 |
| 体态场景门槛 | 分全身/半身/坐姿/遮挡，人工审阅 | V1.0前锁定 |

未锁定的标准不得写为“已通过”。稳定性达不到要求时优先改规则/适配器，必要时报告不能交付评分；不拿一次输出掩盖问题。

## 7. 覆盖与发布门槛

- V0.1：TC-001至042；V0.2增TC-043至048；V0.3增TC-049至054；V1.0增TC-055至059。
- TC-060只在计划开放非本机访问时成为必过；TC-061只在实际交付水印插件时必过。
- 每版同时回归已有版本的来源、授权、评分隔离、删除、异常和版本追溯关键用例。
- 安全边界、未经授权外发、伪造来源、不可评硬评分、删除回写属于发布阻断项，不以页面完成抵消。
- 真实评估引擎不可接入时可以演示本地检查，但不能宣布完整单图评估版验收通过。

执行时逐条登记：用例ID、配置/模型/规则版本、素材许可与哈希、执行时间、通过/失败/阻塞、证据摘要、问题及复验。报告只引用受控素材ID，不把私人照片写进公开测试日志。
